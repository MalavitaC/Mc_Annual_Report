# 麦当劳年度报告

## 这个 Skill 的分工

| 谁 | 负责什么 |
|---|---|
| `templates/report.html`（骨架） | 翻页方式、配色、Logo、装饰层、9 种版式组件 |
| **你（Agent）** | 从订单里挖洞察 → 决定有几页、每页讲什么 → 写文案 → 填进骨架 |

模板里**没有任何文案、指标或页面顺序**。同一份模板，不同的人会得到完全不同的报告。你的任务不是"套模板"，是**找出这个人的数据里有什么值得说的**。

## 四条铁律

1. **页面由洞察决定**，不是由清单决定。没有故事的点，不要为它开一页。
2. **每个数字都要有出处**：能在订单里指到具体那一笔。
3. **宁少不凑**：6 页讲透，好过 12 页注水。
4. **麦麦口吻**：自称「麦麦」，称呼「麦友」，温暖、克制、不说教。

## 执行流程

### 第 1 步：取数

调用 `order-list`（无参数），拿到 `data.list[]`。

字段：`orderId` `createTime` `storeCode` `storeName` `orderStatus` `orderProductList[]` `realTotalAmount`

### 第 2 步：归一化

**拆分**：`orderStatus` 含「取消」→ 取消单；其余 → 有效单。

**逐单补详情**：对有效单调用 `query-order(orderId)`，取 `totalDiscountAmount`、`couponList`、`takeWay`。
失败重试 1 次；仍失败则 `discount` 记 0，并在最终回复里说明。

**商品拍平**：`comboItemList` 里既有真实子项，也有特调说明，必须区分：

- 命中特调特征（含 `()` `（）` `/`，或含「不要 / 不加 / 少 / 多 / 去 / 加 / 换 / 备注」）→ 丢弃
- 其余 → 当作真实子项，`qty` = `itemQuantity` × 父商品 `quantity`，并丢弃父商品名
- 一条不剩 → 用父商品名

> 实测两个例子：`大杯鲜萃咖啡` + `奶油球(不要)/白砂糖(不要)` → 只算咖啡；`可乐` + `可乐大杯` → 只算可乐大杯。

**门店**：用 `storeCode` 聚合；同一门店的 `storeName` 可能有带 / 不带「麦当劳」前缀两种写法，展示名优先取带前缀的。

更多字段细节与实测陷阱见 `references/data-collection.md`。

### 第 3 步：算事实卡

先把这些数字算准，后面所有文案都从这里取。

| 事实 | 算法 |
|---|---|
| 有效单数 / 取消单数 | 计数 |
| 总消费 | Σ `realTotalAmount`（仅有效单） |
| 笔均 | 总消费 ÷ 有效单数 |
| 时间跨度 | `min(createTime)` ~ `max(createTime)` |
| 首单 / 末单 | 按时间排序取两端 |
| 最贵 / 最便宜一单 | 按金额排序取两端（含日期、门店、商品数） |
| 城市 / 门店 | 去重计数；门店访问次数 |
| 时段分布 | 按下单小时分组：凌晨 0–5、早餐 5–10、上午 10–11、午餐 11–14、下午茶 14–17、晚餐 17–21、夜宵 21–24 |
| 星期分布 | 按 `createTime` 推算星期 |
| 月份分布 | 按月分组 |
| 商品去重数 | 拍平后按名称去重 |
| 复购榜 | 按名称聚合数量，降序 |
| 品类结构 | 主食 / 小食 / 饮品 / 甜品（主食关键词优先，避免「美式…麦满分」被算成咖啡） |
| 优惠 | Σ `totalDiscountAmount`；券数量 |
| 取消总额 | Σ 取消单金额 |
| 特殊场景门店 | 店名含机场 / 车站 / 火车站 / 高铁 / 服务区 / 景区 / 医院 / 学校 / 大学 / 大厦 |

**金额一律保留真实小数**：41.5 不能写成 42。

### 第 4 步：挖掘洞察

读 `references/insight-playbook.md`，按里面的判断标准，从事实卡里挑出 **3–6 个真正有意思的点**。

挑选自检（每个洞察都要过）：

- 这句话里有没有**具体名词或具体数字**？
- 这个点是不是**这个人独有**的？换个人还会成立吗？
- 它是不是只是「平均值正常」？——是就丢掉。

优先顺序：**唯一性 > 反差 > 极端 > 重复模式 > 场景**。

### 第 5 步：组页

读 `references/report-schema.md`，把洞察排成页面。

- **首尾固定**：`cover` 开场，`closing` 收尾。
- **中间 4–7 页**，每页承载一个洞察。
- **叙事顺序**：陪伴（发生了什么）→ 关心（有哪些细节）→ 在乎（收尾）。
- **配色节奏**：不要连续两页同色。`red` / `dark` 用于情绪页，`cream` 用于信息页，`yellow` 用于轻快页。
- **版式选择**：见 `report-schema.md` 的「洞察 → 版式」对照表。

### 第 6 步：写文案

- `title` ≤ 14 字，需要换行用 `\n`
- `lead` ≤ 50 字，一句具体的话，不要形容词堆砌
- 标题写**发现**，不写**指标名**：写「你的早餐，比别的时候多」，不写「时段分析」
- 禁止出现：「数据显示」「你的消费情况」「根据订单记录」
- 不用健康评价、不做消费评价

### 第 7 步：注入模板

1. 复制 `templates/report.html` 到输出路径（默认 `<项目根>/mcd-annual-report-<年份>.html`）
2. 用 `edit_file` 替换数据块：

```js
/* ===== REPORT_DATA_BEGIN ===== */
window.REPORT = { "meta": {...}, "pages": [...] };
/* ===== REPORT_DATA_END ===== */
```

只替换 `window.REPORT = {...};` 这一行，保留两个标记。

### 第 8 步：自检 + 交付

- [ ] `pages` 是合法 JSON，页面数 = 圆点数量
- [ ] 每个数字都能回到具体订单
- [ ] 金额小数没被四舍五入（41.5 ≠ 42）
- [ ] 没有连续两页同色
- [ ] 报告里没有地址、手机号、取餐码
- [ ] `meta.coverage` 与真实数据一致

交付时给出：文件路径 + 3 行以内摘要 + 「用浏览器打开，向下滑动翻页」。

## 数据边界

- 接口按**时间窗口**返回，实测可回溯约 265 天，不返回更早年份
- **不做跨年对比**：拿不到上一年数据
- 无支付方式、无取消时刻、无用户昵称
- 热量表是静态快照，季节新品常缺失；若使用必须标注「娱乐估算」

## 隐私红线

**禁止写入**：`storeAddress`、收货人姓名/手机号/地址、骑手信息、`pickupCode`、`lockerCode`、`lockerQrCode`、`accountId`、`payId`、任何 Token。

`closing` 页脚由模板自动附加免责声明，不要删。

## 故障排查

| 现象 | 原因 |
|---|---|
| 页面全白 | 数据块 JSON 语法错误 |
| 出现「没有内容」提示 | `pages` 为空 |
| 门店被拆成两家 | 用 `storeName` 聚合了，改用 `storeCode` |
| 商品里出现「奶油球(不要)」 | 特调说明被当成子项 |
| 页数很少 | 洞察不足，正常；不要硬凑 |
